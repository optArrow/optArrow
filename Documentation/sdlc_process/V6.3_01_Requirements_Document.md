# OptArrow System/Software Requirements Definition Process

## Introduction

This document serves as a comprehensive guide to the OptArrow system, an optimization integration engine designed to provide high-performance data transport and processing capabilities between optimization clients and solver backends. OptArrow is engineered for optimal performance in solving linear programming (LP) and quadratic programming (QP) problems, leveraging the computing power of Python and Julia, with callable functionalities from MATLAB.

### Overview of OptArrow
OptArrow is an advanced optimization integration platform designed to connect clients with solver backends through a stable, high-performance transport layer. At its core, OptArrow facilitates efficient problem-solving for LP and QP challenges using modern computational techniques.

### Primary Objectives
The primary objective of OptArrow is to provide a streamlined and efficient platform for solving complex optimization problems. It connects various computational environments and leverages their strengths for high-speed problem resolution.

### Stakeholders
The key stakeholders for OptArrow include software engineers, researchers, data scientists, and optimization specialists, all of whom require robust optimization tools integrated with comprehensive programming environments.

## Outline of System Capabilities

### Optimization Problem Solving
OptArrow integrates a variety of techniques to solve linear and quadratic programming tasks. It ensures quick and accurate solutions through its robust solver backends.

### Runtime Environments
The system primarily operates using Python and Julia backends, ensuring versatile execution environments that can be invoked from MATLAB, allowing users to utilize the platform that best suits their computational needs.

### Cross-Language Communication
OptArrow employs Apache Arrow to handle cross-language data interchange efficiently. This technology provides seamless communication and data representation transformation between Python and Julia, facilitating robust data processing pipelines.

## Technical Architecture

### Logical Architecture
The logical architecture of OptArrow involves several major components, including the Python Engine Adaptor and the Python Flight Server. These elements are designed to facilitate the routing of optimization tasks from the client to the solver backends, ensuring smooth data transmission and processing.

### Physical Architecture
The physical setup involves the deployment of the Flight Server and the HiGHS Solver Layer, each working in conjunction to handle optimization requests and deliver solutions effectively.

### Data Flow Diagrams
Data within OptArrow transitions from Python dictionaries passed by clients into Apache Arrow IPC streams. These streams are optimized for low-latency data transmission to ensure swift communication with solver backends, eventually directing processed results back into a usable format for the originating environment.

## Interface and Communication Specifications

### Python Engine Adaptor
The Python Engine Adaptor acts as a critical communication bridge, transforming client requests into formats suitable for interaction with the Python Flight Server.

### Python Flight Server
The Flight Server interfaces directly with the HiGHS Solver Layer, receiving optimization tasks, processing them through designated servers, and returning the results.

### HiGHS Solver Layer
OptArrow includes a dedicated solver layer which processes LP and QP tasks using the HiGHS optimization library, known for its performance in handling large datasets.

### Transport Layer Specifications
The transport layer capitalizes on Apache Arrow's advanced serialization capabilities to ensure high throughput and reduced latency in data transport.
